# Безопасность

## Верификация host key

MakoTerm проверяет ключи серверов через файл `~/.ssh/known_hosts`, аналогично OpenSSH.

### Поведение при подключении

| Ситуация | Действие |
|----------|----------|
| Ключ сервера найден в known_hosts | Подключение разрешено |
| Ключ сервера изменился | Подключение **отклонено** с предупреждением |
| Сервер неизвестен | Интерактивный запрос (TOFU) |

### Изменённый ключ

При обнаружении изменения ключа сервера отображается предупреждение вместе с
обоими отпечатками, чтобы их можно было сравнить с сервером независимым каналом:

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Host key for 10.0.0.1:22 has changed.
Offered key:  ssh-ed25519 SHA256:aaaa...
Known key:    ssh-ed25519 SHA256:bbbb...
This could indicate a man-in-the-middle attack.
Remove the offending line from /home/user/.ssh/known_hosts if the change is expected.
```

Подключение отклоняется. Это может означать:
- Сервер был переустановлен
- Атака man-in-the-middle

Для подключения необходимо вручную удалить старую запись из `~/.ssh/known_hosts`.

### TOFU (Trust On First Use)

При первом подключении к неизвестному серверу отображается fingerprint ключа и запрос:

```
The authenticity of host '10.0.0.1:22' can't be established.
ssh-ed25519 key fingerprint is SHA256:xxxxx.
Are you sure you want to continue connecting? (yes/no):
```

При ответе `yes` или `y` ключ сохраняется в `~/.ssh/known_hosts`. При любом другом
ответе подключение прерывается, и в файл ничего не записывается.

### Формат записей

Запись делается для фактического `host:port` в том же формате, что использует
OpenSSH: порт 22 — `host`, нестандартный порт — `[host]:port`. Это позволяет
использовать один и тот же `known_hosts` совместно с системным `ssh` без
расхождений: ключ, принятый MakoTerm на порту 2222, не будет считаться доверенным
для порта 22 того же адреса.

## Хранение данных

### База данных

| Параметр | Значение |
|----------|----------|
| Путь | `~/.makoterm.db` |
| Формат | SQLite (журнал отката, не WAL) |
| Права доступа | `0600` (чтение/запись только для владельца) |
| Файлы журнала | `~/.makoterm.db-journal` и др., права `0600` |

Права 0600 устанавливаются при каждом запуске на саму БД и на любые журнальные
файлы, **до** записи схемы и данных.

### Пароли

**Пароли хранятся в базе данных в открытом виде (plaintext).**

Это известное ограничение. Файл базы данных защищён правами 0600, но шифрование содержимого не реализовано.

**Рекомендация:** используйте SSH-ключи вместо паролей. Поле Password предназначен как запасной вариант.

### Удаление данных физическое

Удаление хостов и групп **не является** «мягким»: записи удаляются из таблиц, а
освободившиеся страницы затираются нулями.

| Механизм | Что делает |
|----------|-----------|
| `Unscoped().Delete(...)` | Физическое удаление строки, а не простановка `deleted_at` |
| `PRAGMA secure_delete=ON` | Затирает содержимое удалённых страниц нулями |
| `VACUUM` после удаления | Перезаписывает файл, убирая следы в свободных страницах |
| Журнал `DELETE` (не WAL) | Предыдущие версии страниц не остаются в sidecar-файле |

Это исправление предыдущего поведения: модели использовали `gorm.Model` с
`DeletedAt`, поэтому удалённый хост оставался в файле БД вместе с паролем в
открытом виде, а «удаление» группы каскадом лишь помечало записи удалёнными.

Режим WAL **намеренно не используется**: в нём предыдущие версии страниц остаются
в растущем файле `-wal` до checkpoint'а, и пароль удалённого хоста продолжал
читаться в этом файле даже после `secure_delete` и `VACUUM`. Регрессионный тест —
`TestDeleteHost_LeavesNoSecretInAnyFile`.

Дополнительно при первом запуске новой версии физически удаляются строки, которые
прежние версии пометили удалёнными, но оставили в файле (`deleted_at IS NOT NULL`).
О количестве удалённых строк сообщается в stderr. Восстановить их невозможно — это
и есть цель исправления.

### SSH-ключи

Приватные ключи читаются из файловой системы по указанному пути. MakoTerm не
копирует и не хранит ключи — только путь к ним. Ведущий `~` раскрывается в
домашний каталог.

Если ключ защищён парольной фразой, она запрашивается у пользователя (ввод без
эха) или берётся из конфигурации; сама фраза нигде не сохраняется.

## Аутентификация

Методы проверяются в порядке приоритета:

| Приоритет | Метод | Источник |
|-----------|-------|----------|
| 1 | SSH Agent | Переменная `SSH_AUTH_SOCK` |
| 2 | Указанный ключ | Поле Key Path хоста |
| 3 | Стандартные ключи | `~/.ssh/id_ed25519`, `~/.ssh/id_rsa` |
| 4 | Пароль | Поле Password хоста |
| 5 | Интерактивный ввод | Запрос пароля, если он не сохранён |

Используется первый успешный метод. Все ключи передаются серверу за один проход
(единый `PublicKeysCallback`), поэтому пустой ssh-agent не блокирует проверку
файловых ключей.

Если хост не имеет сохранённого пароля, MakoTerm запрашивает его интерактивно и
дублирует ответ в `keyboard-interactive` (нужно для части embedded-устройств).

## Файлы и права доступа

| Файл | Создаётся | Права | Содержимое |
|------|-----------|-------|------------|
| `~/.makoterm.db` | Автоматически | 0600 | Группы, хосты, пароли |
| `~/.makoterm.db-journal` | При записи | 0600 | Журнал отката, удаляется после транзакции |
| `~/.ssh/` | Если отсутствует | 0700 | Директория SSH |
| `~/.ssh/known_hosts` | Если отсутствует | 0600 | Ключи серверов |
| `~/.makoterm.log` | Только при `MAKOTERM_DEBUG` | 0600 | Отладочный лог SSH |

Отладочный лог не содержит паролей и парольных фраз: только имена хостов, адреса,
выбранные методы аутентификации и тексты ошибок.

## Legacy-алгоритмы

Для совместимости со старым оборудованием (Cisco 1921 и подобные) включены устаревшие криптографические алгоритмы:

| Тип | Устаревшие алгоритмы |
|-----|---------------------|
| Шифры | `aes128-cbc`, `3des-cbc`, `aes192-cbc`, `aes256-cbc` |
| Key exchange | `diffie-hellman-group14-sha1`, `diffie-hellman-group1-sha1` |
| MAC | `hmac-sha1`, `hmac-sha1-96` |

Эти алгоритмы считаются слабыми, но необходимы для подключения к оборудованию, не поддерживающему современные стандарты. Приложение предпочитает современные алгоритмы (они идут первыми в списке).

> **Замечание.** Списки заданы в коде (`ciphers()`, `keyExchanges()`, `macs()`), а
> не в конфигурации, поэтому ослабление политики происходит всегда — и для
> современных серверов тоже. Направление развития: флаг «strict mode» для
> отключения legacy-алгоритмов и предупреждение в UI, когда соединение
> согласовано на слабом алгоритме.

## Защита от потери данных

| Риск | Защита |
|------|--------|
| Случайное удаление корневой группы | Корень скрыт из UI; БД возвращает `ErrRootGroupProtected` |
| Повреждение БД (нет корня, осиротевшие группы) | `ensureRootGroup()` восстанавливает структуру при запуске |
| Повторное появление демо-данных | Маркер `demo_seeded`; не более одного раза на базу |
| Второй экземпляр приложения | `busy_timeout=5000` вместо ошибки `database is locked` |
| Обрыв сессии за NAT | keepalive-запросы раз в 30 секунд |

## Рекомендации

1. **Используйте SSH-ключи** вместо паролей (предпочтительно Ed25519)
2. **Проверяйте fingerprint** при первом подключении к серверу
3. **Не изменяйте** права на `~/.makoterm.db` — 0600 устанавливается автоматически
4. **Следите за предупреждениями** об изменении host key — они могут указывать на MITM-атаку; сравнивайте оба показанных отпечатка
5. **Не храните пароли** в базе, если есть возможность использовать ключи
6. **Обеспечьте безопасность** рабочей станции — при доступе к файлу БД злоумышленник получит сохранённые пароли
7. **Не включайте `MAKOTERM_DEBUG` без необходимости** и удаляйте созданный лог, если в нём есть внутренние адреса
