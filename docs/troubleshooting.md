# Диагностика проблем

## Ошибка подключения: timeout

### Проблема

```
connect to 10.0.0.1:22: dial tcp 10.0.0.1:22: i/o timeout
```

### Возможная причина

Сервер недоступен, порт заблокирован или неверный адрес. Timeout — 10 секунд.

### Проверка

```bash
# Проверить доступность хоста
ping 10.0.0.1

# Проверить доступность порта
nc -zv 10.0.0.1 22

# Попробовать подключиться стандартным ssh
ssh -v user@10.0.0.1
```

### Решение

- Проверьте адрес и порт в настройках хоста (клавиша `e`)
- Убедитесь, что сервер запущен и SSH-порт открыт
- Проверьте firewall на сервере и на клиенте
- Включите отладочный лог, чтобы увидеть детали подключения:

```bash
MAKOTERM_DEBUG=1 ./makoterm
cat ~/.makoterm.log
```

## Ошибка: host key changed

### Проблема

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!    @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
```

### Возможная причина

- Сервер был переустановлен и SSH-ключ изменился
- Другой сервер отвечает на этом адресе
- Потенциальная MITM-атака

### Проверка

```bash
# Посмотреть текущий ключ в known_hosts
ssh-keygen -F 10.0.0.1

# Получить актуальный ключ сервера
ssh-keyscan 10.0.0.1
```

MakoTerm печатает **оба** отпечатка — полученный от сервера и сохранённый:

```
Offered key:  ssh-ed25519 SHA256:aaaa...
Known key:    ssh-ed25519 SHA256:bbbb...
```

Сравните их с ключом сервера, полученным по независимому каналу
(`ssh-keyscan 10.0.0.1` на доверенной машине), прежде чем что-то менять.

### Решение

Если изменение ожидаемо (переустановка сервера):

```bash
# Удалить старый ключ
ssh-keygen -R 10.0.0.1

# Для нестандартного порта адрес указывается в скобках:
ssh-keygen -R '[10.0.0.1]:2222'
```

При следующем подключении через MakoTerm будет предложено принять новый ключ.

## Ошибка: permission denied

### Проблема

```
connect to 10.0.0.1:22: ssh: handshake failed: ssh: unable to authenticate
```

### Возможная причина

- Неверный пользователь или пароль
- SSH-ключ не принимается сервером
- На сервере отключена аутентификация по паролю

### Проверка

```bash
# Проверить, загружены ли ключи в agent
ssh-add -l

# Попробовать подключиться с verbose
ssh -vvv user@10.0.0.1
```

### Решение

1. Проверьте имя пользователя в настройках хоста (`e`)
2. Убедитесь, что ваш публичный ключ добавлен на сервер (`~/.ssh/authorized_keys`)
3. Проверьте права на файл ключа:

```bash
chmod 600 ~/.ssh/id_ed25519
```

## SSH Agent не работает

### Проблема

MakoTerm не использует ключи из SSH Agent.

### Проверка

```bash
# Проверить, установлена ли переменная
echo $SSH_AUTH_SOCK

# Проверить, есть ли ключи в agent
ssh-add -l
```

### Решение

```bash
# Запустить agent (если не запущен)
eval $(ssh-agent)

# Добавить ключ
ssh-add ~/.ssh/id_ed25519
```

## Запрос парольной фразы для ключа

### Проблема

При подключении MakoTerm запрашивает `Enter passphrase for key ...`.

### Причина

Приватный ключ зашифрован парольной фразой. Это нормальное поведение: раньше такие
ключи молча игнорировались, и подключение падало с невнятной ошибкой
аутентификации.

### Решение

Введите парольную фразу (ввод не отображается). Фраза не сохраняется. Чтобы не
вводить её каждый раз, добавьте ключ в ssh-agent:

```bash
ssh-add ~/.ssh/id_ed25519
```

## Ключ не найден

### Проблема

В настройках хоста указан Key Path, но файл не найден или недоступен.

### Проверка

```bash
# Проверить существование файла
ls -la ~/.ssh/id_ed25519

# Проверить права
stat -f "%Sp" ~/.ssh/id_ed25519  # macOS
stat -c "%a" ~/.ssh/id_ed25519   # Linux
```

### Решение

- Убедитесь, что путь в Key Path указан правильно (поддерживается `~` в начале пути)
- Если ключ недоступен или не читается, MakoTerm выводит предупреждение
  `warning: <путь>: <причина>` перед запросом пароля
- Установите права 0600 на файл ключа:

```bash
chmod 600 /path/to/key
```

## После удаления хоста остался файл с паролем

Это невозможно в текущей версии: удаление физическое, а освободившиеся страницы
затираются (`secure_delete` + `VACUUM`). При первом запуске новой версии также
удаляются записи, которые прежние версии только помечали удалёнными — об этом
сообщается в stderr:

```
MakoTerm: removed N previously soft-deleted row(s) from hosts (they still contained stored credentials)
```

Если это сообщение появилось, значит в базе были «скрытые» удалённые записи с
паролями, и они больше не хранятся.

## Терминал завис в raw mode

### Проблема

После аварийного завершения MakoTerm или SSH-сессии терминал не реагирует на ввод или отображает символы некорректно.

### Решение

Введите вслепую:

```bash
reset
```

Или нажмите `Ctrl+C`, затем введите `reset` и `Enter`.

## Проблемы с отображением

### Проблема

Символы отображаются некорректно, рамки смещены, Unicode-символы (▸, 🦈) не видны.

### Возможная причина

- Терминал не поддерживает UTF-8
- Терминал не поддерживает 256 цветов
- Шрифт не содержит необходимые глифы

### Решение

1. Убедитесь, что терминал поддерживает UTF-8:

```bash
echo $LANG
# Должен содержать UTF-8, например: en_US.UTF-8
```

2. Используйте терминал с поддержкой 256 цветов (iTerm2, Alacritty, kitty, Windows Terminal)
3. Установите шрифт с поддержкой Unicode (JetBrains Mono, Fira Code, Nerd Fonts)

## Ошибка сборки: CGO

### Проблема

```
cgo: C compiler "gcc" not found: exec: "gcc": executable file not found in $PATH
```

### Причина

SQLite требует CGO (C compiler). Пакет `go-sqlite3` компилирует нативный C-код.

### Решение

**macOS:**

```bash
xcode-select --install
```

**Linux (Debian/Ubuntu):**

```bash
sudo apt install gcc build-essential
```

**Linux (Fedora/RHEL):**

```bash
sudo dnf install gcc
```

## База данных заблокирована

### Проблема

```
database is locked
```

### Причина

Одновременно работают два экземпляра MakoTerm (или другой процесс держит БД).

### Решение

Закройте лишний экземпляр. MakoTerm ждёт освобождения блокировки до 5 секунд
(`busy_timeout`), поэтому кратковременная блокировка не приводит к ошибке.

## Повреждение базы данных

### Проблема

Приложение падает при запуске или отображает ошибки при работе с данными.

### Решение

Сначала сделайте копию и попробуйте запустить приложение снова: при старте оно
восстанавливает структуру (создаёт корневую группу, «усыновляет» осиротевшие
группы) и сообщает о изменениях в stderr.

Если это не помогло, переместите файл (не удаляйте сразу) и запустите приложение —
будет создана новая база:

```bash
mv ~/.makoterm.db ~/.makoterm.db.bak
./makoterm
```

> **Внимание:** все сохранённые группы, хосты и пароли останутся только в `.bak`.
> Демонстрационные данные в новой базе создаются один раз; чтобы их не было,
> запустите с `MAKOTERM_NO_DEMO=1`.

## Подключение к старому оборудованию

### Проблема

Не удаётся подключиться к серверу (Cisco, старые Linux-серверы) — ошибка handshake.

### Причина

Некоторое оборудование поддерживает только устаревшие криптографические алгоритмы.

### Решение

MakoTerm включает поддержку legacy-алгоритмов (`3des-cbc`, `diffie-hellman-group1-sha1` и др.). Если стандартный `ssh` подключается с опциями `-c aes128-cbc` или `-oKexAlgorithms=+diffie-hellman-group1-sha1`, то MakoTerm также должен подключиться.

Если всё равно не работает — проверьте, поддерживает ли устройство хотя бы один из алгоритмов, перечисленных в [документации по безопасности](security.md).

Чтобы понять, на каком именно алгоритме произошёл сбой, включите отладочный лог:

```bash
MAKOTERM_DEBUG=1 ./makoterm
tail -50 ~/.makoterm.log
```
