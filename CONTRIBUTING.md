# Участие в разработке

Рекомендации для тех, кто хочет внести изменения в проект.

> Формальных правил contribution в проекте не установлено. Ниже — рекомендуемые практики.

## Workflow

1. Форкните репозиторий
2. Создайте feature-ветку от `main`
3. Внесите изменения
4. Убедитесь, что проверки проходят (см. ниже)
5. Создайте Pull Request

## Перед отправкой PR

```bash
go fmt ./...          # форматирование
go vet ./...          # статический анализ
go test ./...         # все тесты
go test -race ./...   # race detector
go build ./...        # компиляция
```

Все команды должны завершаться без ошибок.

## Тесты

- Добавляйте тесты для новых функций
- Не ломайте существующие тесты
- Database тесты: `database/db_test.go`
- UI тесты: `ui/ui_test.go`

## Стиль кода

- Стандартное форматирование Go (`go fmt`)
- Импорты: stdlib → project → external
- Ошибки: `fmt.Errorf("context: %w", err)`
- Стили UI: только в `ui/theme.go`

## Рекомендации

- Не трогайте SSH-логику (`sshclient/`) при изменениях UI
- Не храните чувствительные данные в открытом виде
- Документируйте новые клавиши в help screen (`renderHelp()` в `model.go`)
- Обновляйте footer (`renderFooter()`) при добавлении новых состояний
- Проверяйте работу на терминалах шириной от 80 символов
