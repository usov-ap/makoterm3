# Участие в разработке

Рекомендации для тех, кто хочет внести изменения в проект.

> Формальных правил contribution в проекте не установлено. Ниже — рекомендуемые практики.

## Workflow

1. Форкните репозиторий
2. Создайте feature-ветку от `main`
3. Внесите изменения
4. Убедитесь, что проверки проходят (см. ниже)
5. Создайте Pull Request

## Перед отправкой PR

```bash
gofmt -l .            # должен быть пустой список
go mod tidy           # и убедитесь, что go.mod/go.sum не изменились
go vet ./...          # статический анализ
staticcheck ./...     # расширенный анализ (как в CI)
go test ./...         # все тесты
go test -race ./...   # race detector
go build -o makoterm .  # компиляция (проверяет CGO/SQLite)
```

Все команды должны завершаться без ошибок. Тот же набор проверок выполняет CI
(`.github/workflows/ci.yml`) на минимальной и текущей версиях Go.

Если запись в системные кэши Go недоступна (контейнер, песочница), используйте
`./scripts/go.sh <команда>` — обёртка держит кэши внутри репозитория.

## Тесты

- Добавляйте тесты для новых функций
- Не ломайте существующие тесты
- Database: `database/db_test.go`
- Логика UI: `ui/ui_test.go`
- Геометрия и рендеринг: `ui/layout_test.go` — если тест касается вывода на экран,
  добавьте проверку инварианта (высота/ширина не превышают размер терминала)
- SSH: `sshclient/manager_test.go` — `startTestServer` поднимает SSH-сервер в
  процессе теста, реальная сеть и ключи пользователя не используются

## Стиль кода

- Стандартное форматирование Go (`go fmt`)
- Импорты: stdlib → project → external
- Ошибки: `fmt.Errorf("context: %w", err)`
- Стили UI: только в `ui/theme.go`

## Важные ограничения

- **Удаление данных должно оставаться физическим.** Не добавляйте `gorm.DeletedAt`
  и не заменяйте `Unscoped()`-удаления: с «мягким» удалением пароли остаются в
  файле БД. См. `DeleteHost`/`DeleteGroup` и `docs/security.md`.
- **Корневую группу нельзя удалять или переименовывать** — она скрыта из UI, а БД
  возвращает `ErrRootGroupProtected`.
- **Не ослабляйте проверку host key.** Отказ при изменившемся ключе и запрос TOFU
  для неизвестного — осознанное поведение.
- **Не логируйте секреты.** В отладочный лог (`MAKOTERM_DEBUG`) не должны попадать
  пароли и парольные фразы.
- Не трогайте SSH-логику (`sshclient/`) при изменениях UI.

## Рекомендации

- Документируйте новые клавиши в help screen (`renderHelp()` в `model.go`)
- Обновляйте footer (`renderFooter()`) при добавлении новых состояний
- Проверяйте работу на терминалах шириной от 80 символов и на узких (40–60): footer
  и колонки должны оставаться в пределах экрана
- Не создавайте `lipgloss.NewStyle()` вне `ui/theme.go`
- Пользовательские изменения поведения и breaking changes фиксируйте в
  `CHANGELOG.md`
